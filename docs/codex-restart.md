# Reviewed Codex restart

Successful installation or approved repair opens a restart prompt, not clicking Reinstall or cancelling its review. **Later** leaves a persistent reminder. Automatic restart identifies one desktop application in the main process and requires explicit confirmation that active tasks are finished. The renderer supplies only an expiring opaque token; it cannot choose commands, paths, or process IDs. The runtime owner holds an idle drain across restart and resumes it afterward, including on failure. Work outside the bridge cannot be declared idle.

The reminder places Restart options in a dedicated action area beside the explanation on wide layouts and below it on narrow layouts. Opening that dialog only checks availability; it never restarts Codex. Manual fallback explains the observed reason, including active bridge work, ambiguous application identity, or unsupported environment. Unrelated background failures remain in global action feedback rather than appearing to be restart failures.

Linux discovers installed applications through a narrow absolute-executable desktop entry and matches running processes by executable, PID, and start time, independently of the window manager. An unambiguous installed application can launch when closed. Automatic graceful restart additionally requires matching local X11 windows that advertise `WM_DELETE_WINDOW`; it requests normal close through `wmctrl`. A running Wayland application, custom wrappers, unavailable close utilities, or ambiguous entries retain manual restart guidance. macOS identifies the `com.openai.codex` running application and requests normal termination through AppKit, then opens its observed bundle. Windows requires an OpenAI-signed Codex executable with a main window, requests `CloseMainWindow`, and relaunches that executable. Background processes, declined close, discovery failures, or failure to exit within 30 seconds are manual outcomes; no force-kill is used. Named CLI profiles retain manual session-restart guidance.

Process launch is not configuration verification. The reminder clears only after observed application-instance replacement and a subsequent successful model-catalog request. If the launcher lacks that evidence, the reminder remains. Restart-controller and native-adapter fixtures are not native Windows/macOS acceptance.

Restart evidence persists a target-specific configuration revision and application baseline as configuration changes are reconciled, without requiring the restart dialog to be opened. The revision includes Codex TOML and runtime inputs affecting its model catalog, including account model availability, interaction mode, protocol, Bigger Context, Zero Risk Pro, and runtime release. An earlier restart cannot satisfy a later catalog-only change. Unrelated approval preferences and generated cache refreshes do not invalidate this evidence. Setup previews use the same catalog configuration key when explaining whether a restart is required.

The platform contracts are documented by [Apple AppKit](https://developer.apple.com/documentation/appkit/nsrunningapplication?language=objc), [Microsoft CloseMainWindow](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.closemainwindow), and the [Extended Window Manager Hints specification](https://specifications.freedesktop.org/wm/latest-single/). The user-facing confirmation follows the [Codex troubleshooting guidance](https://learn.chatgpt.com/docs/reference/troubleshooting) to finish active work before restarting.
