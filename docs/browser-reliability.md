# Browser identity and safe launcher transitions

Connector lookup is scoped to connector-owned rows, not every menu-shaped element in the page. The visible exact-name candidate must be unique before keyboard activation, and the selected composer pill must independently confirm the requested connector. A sidebar conversation with the same name is not a connector candidate. A strictness race is a non-retryable identity failure, not a reason to repeat browser preparation.

The offline selector contract runs with `CHATGPT_TEST_CHROME_EXECUTABLE` pointing to an installed Chromium executable: `bun test tests/connector-menu-dom.test.ts`. It launches a fresh, unauthenticated browser, blocks page network requests, and renders synthetic HTML. Without an explicit executable the browser test is skipped; ordinary worker and reconnect tests still run. This fixture proves locator behavior, not current ChatGPT service compatibility.

The authenticated loopback control endpoint `POST /v1/launcher/shutdown-idle` accepts an empty JSON object. It refuses overlapping shutdown and new browser admissions while draining. It uses the runtime supervisor's non-cancelling, non-forcing shutdown path, persists the session, and acknowledges before closing the control connection. A successful acknowledgement must be followed by observed process exit before another launcher uses the profile. Busy/refused shutdown returns HTTP 409. Launchers predating the endpoint return 404; callers must not silently substitute process termination.

Normal user-initiated Quit retains its existing cancellation behavior. Idle shutdown is a separate contract for supervised development and channel transitions, not a change to what Quit means.

Persisted browser capture errors contain only structural categories, not arbitrary exception names, messages, or causes. Launcher logs and legacy exports omit recognized browser exception/DOM dumps as whole strings because partial redaction cannot reliably remove private rendered content. Screenshots remain explicit opt-in private evidence; diagnostic files and recovery snapshots should never be uploaded without review.

Same-turn native steering establishes direction from unchanged input prefixes, including the earlier user instruction. The registry cancels only a proved predecessor owned by the same native task and turn, then joins its physical browser cleanup before admitting the replacement. The replacement receives the native history, including completed tool outputs; the adapter does not re-emit the predecessor’s tool calls. Retained predecessor tombstones and descendant lineage reject delayed older requests after replacement completion or retirement. This protection shares the bounded session registry’s replay lifetime. Repeating identical instruction content within a turn currently produces an explicit revision-conflict error because the execution identity cannot distinguish that revision safely.

Native user message IDs distinguish repeated instruction text within one turn. The execution key retains that ID together with the instruction content, model, effort and task/turn identity. Exact tool continuations reuse the same key; compaction resolves the same source ID when retiring the response it replaces. Prefix lineage still establishes whether an instruction is a newer steering revision and rejects delayed predecessors. Legacy messages without stable IDs retain the conservative conflict behavior when identical content cannot identify a new execution; absence of identity is not permission to replay.

A rejected lifecycle acknowledgement remains distinct from the helper's subsequent settlement. A confirmed helper AbortError returns the original local failure. A later helper error or unexpected successful response returns nonretryable `browser_helper_cancellation_unconfirmed`, preserving the local failure and any helper failure as causes. Local cancellation is not evidence that physical cleanup succeeded.

The continuation cache coalesces disk snapshots behind one asynchronous writer, so slow file replacement does not block the serving event loop. Updates arriving during a write remain pending for a subsequent snapshot. Runtime shutdown joins pending snapshots before closing diagnostics. Replacement uses a private temporary file and atomic rename; a failed replacement retains the previous snapshot and reports `response_state_persistence_failed`, while in-memory continuations remain usable. This is best-effort restart recovery, with existing entry and total snapshot limits; it does not guarantee persistence after a process crash or power loss.

Effort selection reads the slider's semantic range and value together. If the picker disappears during setup, the worker can reopen it once before any effort keypress and use the newly observed value. A missing or malformed replacement fails with `model_control_unavailable`; disappearance after an effort keypress does not trigger replay of that keypress. Capability inspection uses the same semantic-state reader.

Native system turns, including task titles, can declare orchestration tools without a workspace envelope. After the ordinary resolver reports missing trusted environment, a read-only root system turn with a current native revision can retain the recognized request-input, clock and collaboration declarations in a request-local native-only context. That context contains no cwd, roots or sandbox authority and is never written to the thread environment store. Native remains the executor and permission owner. Unknown tools, filesystem context fields and ordinary user/subagent requests still require trusted workspace authority. The broker rejects undeclared or freeform native-only invocations and prevents an active turn from switching between native-only and workspace contexts. Permissions instructions remain part of the prompt.
