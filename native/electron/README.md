# Embedded WebAuthn runtime

The launcher uses Chromium's WebAuthn request and relying-party validation. The reviewed Electron patch adds the missing UI callbacks for a security-key PIN and hybrid phone pairing, plus the permission feature needed to load the official 1Password extension. The separate Chromium patch retries a bounded BlueZ scan-start failure in hybrid discovery; each delayed retry uses a weak callback so a cancelled request does not retain the discovery. When BlueZ reports `InProgress`, the patch shares the scan only if the adapter confirms discovery is active; otherwise the failure remains visible. These patches do not substitute an authenticator or store passkey credentials.

The patched session emits `webauthn-pin-request` with the request ID, relying party, originating frame, PIN reason/error, minimum length, attempts and one response callback; `webauthn-hybrid-qr` with the same owner, an ephemeral FIDO QR string, Bluetooth state and a bounded action callback; `webauthn-bluetooth-status`; and `webauthn-request-closed`. A successful native request includes only Chromium's coarse winning-authenticator category (`phone`, `platform`, or `other`); the launcher keeps this separate from the method selected in its prompt. `other` does not prove a hardware key or password manager. The existing `select-webauthn-account` event remains authoritative for discoverable credentials. The launcher accepts replies only from its own prompt window while the initiating frame and URL remain current.

The manifest pins the Electron, Chromium, and build-tools revisions and both patch hashes are recorded with the compiled binary. Use a dedicated build root with enough space for Chromium and a local Git cache; this checkout uses `/ai_models` so the source and compiled runtime do not fill the repository filesystem.

Create a build-tools checkout at the manifest's commit and install its locked dependencies. Run `e init codex-web-gpt-v44-release --root=BUILD_ROOT --import release --out Release --remote-build none --use-https` before adding Electron source to the new root. Clone Electron tag `v44.4.4` into `BUILD_ROOT/src/electron`, check that its commit matches the manifest, and run `SENTRYCLI_SKIP_DOWNLOAD=1 e sync --no-history`. This local build does not upload crash symbols. Set that build config's `GIT_CACHE_PATH` to a cache on the same large filesystem and its GN arguments to the manifest's `gnArgs`. The local runtime keeps release layout while disabling profile-guided optimization until functional acceptance.

The explicit `is_debug=false` in `gnArgs` is required: overriding `is_official_build=false` otherwise restores GN's debug default even under an output directory named `Release`, enabling V8 checks that the pinned Node integration cannot compile. The `symbol_level=0` setting keeps this functional release build within the owned build volume. Verify the resolved values with the pinned `src/buildtools/linux64/gn args out/Release --list --short` before rebuilding.

The Linux build needs libnotify public headers that the pinned Debian sysroot omits. `scripts/build-electron-webauthn.ts` verifies the five vendored 0.8.8 headers under `libnotify-headers/` against the manifest and copies them only into that owned sysroot; a different existing header fails closed. This is a build input, not a copied personal configuration or a replacement for the runtime's optional libnotify loader.

Electron's dependency patch hooks are not safe to reapply after a late Yarn hook failure. If only that hook failed, finish its pinned Yarn install in the Electron checkout with `SENTRYCLI_SKIP_DOWNLOAD=1` instead of repeating the whole sync. An owned checkout left inside `git am` by a repeated hook must be inspected before clearing that state.

Set `CODEX_WEB_GPT_ELECTRON_SOURCE` to the absolute `BUILD_ROOT/src/electron` path and `CODEX_WEB_GPT_ELECTRON_BUILD_TOOLS` to the build-tools checkout. Run `bun scripts/build-electron-webauthn.ts --prepare-only` to check revisions and the patch, then run it without `--prepare-only` to build. The script refuses a different Electron revision or build-tools revision and applies the patch only when it is absent.

The launcher package must use the compiled runtime. Stock Electron 44.4.4 still reports that it does not support a FIDO2 PIN, so compiling this patch and selecting its output are required before the packaged sign-in path can be accepted.

For local Linux development, set `CODEX_WEB_GPT_ELECTRON_EXECUTABLE` to `BUILD_ROOT/src/out/Release/electron` and run `bun run dev` from `launcher/`; the command verifies the build record in the same output directory before starting. `bun run start` uses that same executable with the isolated DEV profile. For packaging, set `CODEX_WEB_GPT_ELECTRON_DIST` to `BUILD_ROOT/src/out/Release/dist.zip`. The package embeds a build record and checks the native Session patch identity at startup; Linux also checks the executable hash. Upstream automatic updates stay disabled because an upstream stock release would remove the patched authentication delegate. Native Windows and macOS packaging and authentication still require separate platform verification.

Set `CODEX_WEB_GPT_ARTIFACTS_DIR` to a fresh absolute directory on the build volume when packaging and running `smoke:package` so existing local artifacts remain untouched and the AppImage does not consume the repository filesystem.
