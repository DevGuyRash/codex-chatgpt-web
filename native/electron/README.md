# Embedded WebAuthn runtime

The launcher uses Chromium's WebAuthn request and relying-party validation. The reviewed Electron patch adds the missing UI callbacks for a security-key PIN and hybrid phone pairing, plus the permission feature needed to load the official 1Password extension. One Chromium patch retries a bounded BlueZ scan-start failure in hybrid discovery; each delayed retry uses a weak callback so a cancelled request does not retain the discovery. When BlueZ reports `InProgress`, the patch shares the scan only if the adapter confirms discovery is active; otherwise the failure remains visible. A second Chromium patch backports [the upstream CSS fallback crash fix](https://github.com/chromium/chromium/commit/3e5d0b609aab74d7b0540ce98221cb7ae77ae230), which removes an invalid parser assertion hit by current ChatGPT documents in the pinned runtime. These patches do not substitute an authenticator or store passkey credentials.

The patched session emits `webauthn-pin-request` with the request ID, relying party, originating frame, PIN reason/error, minimum length, attempts and one response callback; `webauthn-hybrid-qr` with the same owner, an ephemeral FIDO QR string, Bluetooth state and a bounded action callback; `webauthn-bluetooth-status`; and `webauthn-request-closed`. A successful native request includes only Chromium's coarse winning-authenticator category (`phone`, `platform`, or `other`); the launcher keeps this separate from the method selected in its prompt. `phone` identifies Chromium's hybrid phone authenticator. `platform` includes operating-system mediated APIs that may route external devices, and `other` does not prove a hardware key or password manager. The existing `select-webauthn-account` event remains authoritative for discoverable credentials. The launcher accepts replies only from its own prompt window while the initiating frame and URL remain current.

The manifest pins the Electron and build-tools commits, the public Chromium base commit for the Electron tag, and the fork patch hashes; all are recorded with the compiled binary. Electron's sync applies its own Chromium patch list as local commits, so the resulting Chromium HEAD varies with local commit metadata. The build verifies that the public base is its ancestor and that the pinned Electron patch-list count matches the applied commit count. Use a dedicated build root with enough space for Chromium and a local Git cache. On this host the source, output, and Git cache previously occupied about 96 GiB, so the 32 GiB `/tmp` filesystem cannot hold a native rebuild. Choose a build volume with adequate free space, keep only the reviewed `dist.zip`, build record, and extracted runtime after packaging, and remove disposable source and cache when finished.

Create a build-tools checkout at the manifest's commit and install its locked dependencies. Run `e init codex-web-gpt-v44-release --root=BUILD_ROOT --import release --out Release --remote-build none --use-https` before adding Electron source to the new root. Clone Electron tag `v44.4.4` into `BUILD_ROOT/src/electron`, check that its commit matches the manifest, and run `SENTRYCLI_SKIP_DOWNLOAD=1 e sync --no-history`. This local build does not upload crash symbols. Set that build config's `GIT_CACHE_PATH` to a cache on the same large filesystem and its GN arguments to the manifest's `gnArgs`. The local runtime keeps release layout while disabling profile-guided optimization until functional acceptance.

The explicit `is_debug=false` in `gnArgs` is required: overriding `is_official_build=false` otherwise restores GN's debug default even under an output directory named `Release`, enabling V8 checks that the pinned Node integration cannot compile. The `symbol_level=0` setting keeps this functional release build within the owned build volume. Verify the resolved values with the pinned `src/buildtools/linux64/gn args out/Release --list --short` before rebuilding.

The Linux build verifies the pinned Debian sysroot's libnotify 0.7.9 pkg-config file and four public headers against the manifest. It uses those headers directly and does not overwrite the sysroot. A changed sysroot fails closed until its build input is reviewed. This does not replace the runtime's optional libnotify loader.

Electron's dependency patch hooks are not safe to reapply after a late Yarn hook failure. If only that hook failed, finish its pinned Yarn install in the Electron checkout with `SENTRYCLI_SKIP_DOWNLOAD=1` instead of repeating the whole sync. An owned checkout left inside `git am` by a repeated hook must be inspected before clearing that state.

Set `CODEX_WEB_GPT_ELECTRON_SOURCE` to the absolute `BUILD_ROOT/src/electron` path and `CODEX_WEB_GPT_ELECTRON_BUILD_TOOLS` to the build-tools checkout. Run `bun scripts/build-electron-webauthn.ts --prepare-only` to check revisions and the patch, then run it without `--prepare-only` to build. The script refuses a different Electron revision or build-tools revision and applies the patch only when it is absent.

The build defaults to eight local jobs. Choose `CODEX_WEB_GPT_ELECTRON_JOBS` from measured available memory as well as CPU count, and monitor the host's swap and memory-pressure counters during a full compile. A low process-tree RSS sample is not enough: a high-concurrency Blink phase can push unrelated desktop pages into swap even when the compiler's own swap PSS remains zero. Ninja reuses completed objects after a job-count change.

The launcher package must use the compiled runtime. Stock Electron 44.4.4 still reports that it does not support a FIDO2 PIN, so compiling this patch and selecting its output are required before the packaged sign-in path can be accepted.

For local Linux development, set `CODEX_WEB_GPT_ELECTRON_EXECUTABLE` to `BUILD_ROOT/src/out/Release/electron` and run `bun run dev` from `launcher/`; the command verifies the build record in the same output directory before starting. `bun run start` uses that same executable with the isolated DEV profile. For packaging, set `CODEX_WEB_GPT_ELECTRON_DIST` to `BUILD_ROOT/src/out/Release/dist.zip`. The package embeds a build record and checks the native Session patch identity at startup; Linux also checks the executable hash. Upstream automatic updates stay disabled because an upstream stock release would remove the patched authentication delegate. Native Windows and macOS packaging and authentication still require separate platform verification.

Set `CODEX_WEB_GPT_ARTIFACTS_DIR` to a fresh absolute directory when packaging and running `smoke:package` so existing local artifacts remain untouched. `/tmp` is suitable for the smaller package and smoke scratch when it has enough free space; move the artifact you intend to retain to persistent storage and remove the scratch directory after verification.
